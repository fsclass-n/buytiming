# PickTiming 10분 발표·시연 영상 제작 프롬프트

`프로젝트_발표자료.pptx` 발표와 실제 플랫폼 시연을 이어 붙여 **면접관용 10분 MP4(`3조_final.mp4`)**를 만들 때 쓰는 프롬프트입니다.
아래 `---` 사이를 영상 기획자·편집자·AI에게 그대로 전달합니다. 사실 정보는 저장소 `main`(코드 기준 `279a4ce`)과 공개 서비스에서 확인한 값입니다.

> AI가 MP4를 직접 녹화할 수는 없습니다. 이 프롬프트로 **대본·동선·편집 사양·README**를 완성하고,
> 영상은 사람이 녹화하거나 9장의 자동 제작 방법(PowerPoint 비디오 내보내기 + Playwright 화면 녹화 + ffmpeg)으로 만듭니다.

## 1. Role & Context

당신은 웹 플랫폼 발표 전문 기획자이자 테크니컬 스토리텔러입니다.
면접관이 **10분 안에** PickTiming의 문제 정의, 시스템 구성, 핵심 기능, 권한 설계, 기술적 완성도를 이해하도록
**PPT 발표 → 화면 전환 → 일반 회원 시연 → 관리자 시연 → 클로징** 흐름의 10분 MP4 제작 자료를 만드세요.

면접관은 “기능이 많은가”보다 아래 다섯 가지를 봅니다. 모든 장면이 이 중 하나 이상을 증명해야 합니다.

1. 문제를 정확히 정의했는가 (‘어디서 살까’에서 ‘언제 살까’까지)
2. 실제로 동작하는가 (클릭 결과가 화면에서 바로 바뀌는가)
3. 왜 그렇게 설계했는가 (장면마다 기술 근거 한 줄)
4. 권한과 데이터를 안전하게 다루는가 (회원·관리자 분리, 차단 장면)
5. 한계를 정직하게 말하는가 (데모 데이터, 미측정 지표)

- 한 줄 정의: 여러 쇼핑몰의 실구매가와 가격 흐름을 보여 주고, 지금 살지 기다릴지 판단을 돕는 서비스
- 팀(가상 인물): **박미금**(조장·PM·데이터/AI, 발표자, 남성) · **김모란**(백엔드·배포) · **이오리**(프런트엔드·UI/UX) · **홍기흥**(RPA·데이터 수집)
- 구성: React·Vite·Tailwind(화면) → FastAPI(서버, API 34개) → TiDB(DB, 테이블 12개) / RPA 수집기(1시간 주기) / scikit-learn 적기 점수 / Google Gemini 설명(숫자 검증 후 실패 시 정해진 설명으로 대체)
- 서비스 주소: 데모 `https://picktiming.netlify.app`(브라우저 목업 데이터, 서버·DB 연결 없음) · 운영 `https://picktiming.onrender.com`(FastAPI + TiDB) · GitHub `https://github.com/fsclass-n/picktiming`
- 확인된 검증: 백엔드 테스트 51건, RPA 테스트 11건, 브라우저 시나리오 9개, CI(SQLite·MySQL 8·Docker) 통과
- 사용 금지 수치(근거 없음): 설문 34명·79%·68%, F1 0.61/0.78/0.79 실적, 수집 성공률 97.5%, 관심 상품 300종, 환각 0건, JSON 99.8%, 응답 2.2초, 호출 −62%, 테스트 111건, 부하 오류율 0.3%, v1.0/v1.1 배포
- 발표 PPT: `docs/프로젝트_발표자료.pptx` = **18장 기술 면접 포트폴리오**(장마다 발표자 노트에 설명 포인트·예상 질문)

### 2.1 계정 분리의 실제 구현 (그대로 설명)

- 로그인 화면은 하나이고, **계정의 역할(USER / ADMIN)**로 기능을 나눕니다. 로그인 화면에 `일반 사용자 테스트`·`관리자 테스트` 버튼이 있습니다.
- 관리자 메뉴 `관리자 센터`는 ADMIN만 보입니다. 일반 회원이 `/admin`에 들어가면 **“관리자 전용 화면입니다”**로 막힙니다.
- 서버도 관리자 API를 ADMIN 역할로 다시 검사합니다. 테스트 관리자는 **조회 전용**이라 권한 변경을 누르면 “테스트 관리자 계정은 회원 권한을 변경할 수 없습니다(조회만 가능)” 오류가 나옵니다.
- “로그인 페이지가 두 개”라고 말하지 않습니다. “하나의 로그인, 역할에 따른 화면·API 분리”로 설명합니다.

### 2.2 시연 데이터 원칙

- 주 시연은 **Netlify 데모**에서 합니다. 콜드 스타트가 없고 운영 DB를 바꾸지 않습니다. 화면 상단의 “PickTiming 체험 공간 · 상품과 가격은 데모 데이터입니다” 배너를 처음에 짚습니다.
- 관리자 화면의 숫자(F1 0.79, 수집 성공률, AI 호출 수 등)는 **데모 데이터**입니다. 성과로 읽지 않고 “이런 지표를 모니터링한다”고만 말합니다.
- 데모의 AI 조언은 `규칙 기반 분석` 표시가 나옵니다. “실제 서버에서는 Gemini가 같은 형식으로 답하고, 숫자를 검증한다”고 설명합니다.
- 운영(Render)에서는 `/docs`(API 문서)와 `/health`만 보여 줍니다. 운영 DB에 회원가입·권한 변경·대량 등록을 하지 않습니다.

## 6. 파트별 상세 대본 작성 규칙

- 각 파트: **시간 · 장면 제목 · 핵심 메시지 · 실제 대본 · 전환 멘트**를 씁니다.
- 말하기 속도: 초당 3.5~4음절. 클릭 직후 0.5초 쉬고 결과를 말합니다(“누르면… 이렇게 바뀝니다”).
- 장면마다 **기능 한 문장 + 기술 근거 한 문장**을 넣습니다. 예: “배송비를 더해 비교합니다. 가격 기록에 판매가와 배송비, 실구매가를 함께 저장합니다.”
- 금지: “완벽하게”, “정확도 높은”, “실시간 AI 예측 보장” 같은 과장, 데모 수치를 성과처럼 읽기, 측정하지 않은 응답 속도.
- 클로징에서 한계 1개와 다음 단계 1개를 말합니다(예: 판정 적중률 집계).

- [ ] 일반 회원 로그인 → 관리자 화면 차단 → 관리자 로그인 → 조회 전용 거부까지 **계정 분리 장면 4개** 포함
- [ ] PPT 구간은 1~16장, 클로징은 17·18장이며 장별 시간이 5장 표와 일치
- [ ] 장면마다 기능 + 기술 근거가 한 문장씩 있고, 전문 용어는 쉬운 말로 먼저 설명
- [ ] 데모 배너·“데모 수치” 자막이 보이고, 데모 숫자를 성과로 말하지 않음
- [ ] 토큰·비밀번호·환경 변수·개발자 도구가 화면에 나오지 않음
- [ ] 자막과 음성이 일치하고, 음량이 일정(−16 LUFS)
- [ ] `3조_final.mp4` 95MB 이하·H.264·1080p, 하이라이트 10MB 이하
- [ ] README의 영상 링크·하이라이트·스크린샷 경로가 실제로 열림
