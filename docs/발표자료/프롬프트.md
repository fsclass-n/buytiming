### 2.4 동작 방식
1. 수집: RPA가 1시간 주기로 등록 판매처 가격 수집 — robots.txt 확인 불가 시 수집 안 함, 요청 간격 3초, 재시도 3회(3·6·12초), 직전 가격 대비 ±50% 이상치 제외
2. 적재: `POST /rpa/prices/bulk`(X-RPA-KEY) — 같은 판매처·같은 시간대 두 번째 가격은 저장하지 않음(두 수집기 중복 방지)
3. 판정: 적기 점수 = (1 − 7일 내 5% 하락 확률) × 70 + (1 − 90일 가격 백분위) × 30 → 70점 이상 지금 구매 · 40~69 조금 대기 · 40 미만 기다리기 · 이력 30일 미만 판단 보류. 활성 모델이 없으면 규칙 확률 사용. 재학습은 F1이 운영 모델 이상일 때만 교체
4. 설명: Gemini 응답 속 숫자를 입력 수치와 대조 → 불일치 시 1회 재요청 → 실패·오류·키 없음이면 정해진 설명으로 대체. 조언 캐시 24시간, 사용자별 일일 한도(기본 20회)
5. 알림: 가격 저장 직후 목표가 도달·판정 변화 알림 생성(24시간 중복 방지), 사이트 내 알림
6. 권한: 사용자 JWT, 수집기 X-RPA-KEY(hmac 비교), 관리자 ADMIN 역할. 본인·마지막 관리자 권한 변경 금지, 테스트 관리자 조회 전용. 운영에서 기본 비밀값이면 서버 기동 거부

### 2.5 기능
- 일반 회원: 상품 검색·필터·정렬, 판매처별 실구매가(판매가+배송비) 비교, 7·30·90일 가격 흐름, 구매 타이밍 신호등, AI 조언·상담, 관심 상품·목표가, 가격 알림, 3단계 회원가입(약관 → 계정·관심 카테고리 → 첫 알림)
- 관리자: 회원 기능 전체 + 회원 검색·권한 변경, 수집 현황·작업 로그, 모델 버전, AI 호출·응답·검증 현황
- 비회원: 홈·서비스 안내·가입만
- 설정이 필요한 기능: 소셜 로그인(Google·Naver·Kakao 키), 참가격·네이버 API 키, S3

### 2.8 문제 해결 사례 (포트폴리오용, 저장소 기록 근거)

2. 두 수집기(EC2·Actions)가 같은 DB에 저장 → 시간대 중복 방지, `test_bulk_prices_skip_same_hour`
3. LLM이 입력에 없는 숫자 생성 위험 → 숫자 대조·재요청·대체, 가짜 클라이언트 테스트 3건
