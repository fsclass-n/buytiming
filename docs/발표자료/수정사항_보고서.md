## 1. 기존 PPT 분석

### 1.1 유지한 장점

| 기존 내용 | 유지 방식 |
|---|---|
| “어디서 살까”에서 “언제 살까”까지라는 문제 정의 | 3장 결론 문구와 8장 차별성의 중심 메시지로 유지 |
| 등록 → 비교 → 판정 → 조언 → 알림 사용자 여정 | 2장 5단계 흐름(수집·비교·판단·설명·알림)으로 정리 |
| 적기 점수 산식과 판정 기준(70점/40점, 30일 보류) | 8장 기술 특징, 설계 산출물에 그대로 유지 |
| Gemini 숫자 대조 검증 → 재요청 → 템플릿 대체 | 5장 구성도와 8장 기술 특징으로 유지 |
| RPA 수집 원칙(robots.txt·3초 간격·이상치 제외) | 5장 구성도 보조 설명으로 유지 |
| 교육 과정명, 3조, 팀원 4명, 발표회 일자 | 표지에 유지(조장 표기만 요청에 따라 정정) |
| 향후 계획(카드·쿠폰, 적중률 공개, 제휴 API, 푸시) | 9장 향후 계획으로 유지 |

### 1.2 기존 문제점

| 구분 | 문제 | 영향 |
|---|---|---|
| 시간 | 13장·15분 발표 기준(발표 9분) | 3분 안에 말할 수 없음 |
| 구조 | 목차·팀 일정·기술 3장이 앞쪽에 집중, 기대 효과·권한 비교 없음 | 심사위원이 “무엇을 왜 만들었는지”보다 기술 세부를 먼저 봄 |
| 사실 | 서비스명 BuyTiming, 조장 표기, Vanilla JS·Bootstrap 화면 | 현재 PickTiming·React 구현과 불일치 |
| 근거 | 설문 79%·68%, F1 0.79, 수집 성공률 97.5%, 환각 0건, 2.2초, 테스트 111건, 오류율 0.3% | 측정 원자료가 없어 발표 시 사실처럼 전달될 위험 |
| 가독성 | 표·수치 카드 위주, 작은 글씨 다수 | 비전문가가 한눈에 이해하기 어려움 |
| 시각 자료 | 실제 화면 캡처 없음, 시스템 구성도 단순 나열 | 구현 완성도가 화면으로 드러나지 않음 |
| 디자인 | 보라 단색 배경, 슬라이드별 위계 차이 | 요청한 Navy Tech 톤과 불일치 |

## 2. 변경된 구성

### 2.1 기존 13장 → 최종 10장

| 최종 | 슬라이드 | 기존 출처 | 처리 |
|---|---|---|---|
| 1 | 표지 | 1 표지 | 서비스명·발표자 정정, 실제 홈 화면 추가 |
| 2 | 프로젝트 소개 | 4 서비스 소개 | 한 문장 정의 + 목적·서비스·사용자·가치 + 5단계 흐름 |
| 3 | 개발 배경 | 3 프로젝트 배경 | 설문 수치 삭제, 문제 카드 3개와 예시 그래프 |
| 4 | 개발 목표 | 3·12 일부 | PROBLEM → SOLUTION → VALUE, 개발 목표 4개 |
| 5 | 시스템 구성 | 6 시스템, 7 RPA | 사용자→프론트엔드→백엔드→DB + 수집·분석·Gemini, 배포 환경 |
| 6 | 주요 기능 | 4 서비스, 11 시연 | 실제 화면 4개와 기능명 |
| 7 | 계정별 기능 비교 | (신규) | 일반 회원 vs 관리자 좌우 비교, 권한 보호 |
| 8 | 핵심 기술 및 차별성 | 8 판정, 9 Gemini, 10 테스트 | 개선점·기술·편의성·구현 성과 4분면 |
| 9 | 기대 효과 | 12 성과·향후 계획 | Before/After 4쌍, 향후 계획 |
| 10 | 마무리 | 13 감사, 11 시연 | 핵심 메시지, 감사 인사, 7분 시연 순서 |

목차(기존 2)와 조 구성·일정(기존 5)은 3분 발표에서 제외하고 기획 산출물에 남겼습니다.

### 4.3 이미지

- 공개 Netlify 데모에서 실제 화면 12종을 캡처했습니다(`assets/`, 출처 `capture-manifest.json`).
- 화면은 비율을 유지한 채 위쪽 기준으로 잘라 넣었고, Netlify 배지는 캡처 전에 숨겼습니다. 앱 UI는 수정하지 않았습니다.
- 관리자 화면의 수치(F1 0.79, 성공률 등)는 데모 데이터이므로 “데모 수치”로 표기했습니다.
