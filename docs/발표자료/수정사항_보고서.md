# 최종 발표 자료 수정 보고서

검토 기준: 코드 `279a4ce`, 기존 13장 PPT와 대응 PDF, 단계별 HWPX·PDF 10쌍, 운영 문서.
발표자는 사용자 지정에 따라 **3조 조장 박미금**입니다. 원본 구성원 김길동·이오리·홍기흥을 유지했습니다.

## 1. 수정 목적

원본의 “수집 → 비교 → 구매 시점 판단 → AI 설명 → 알림”이라는 서비스 의도를 유지하면서
PPT 3분과 웹 시연 7분에 맞게 설명을 압축했습니다. 이전에 승인·반영된 서비스명 PickTiming과
현행 React UI를 기준으로 내용을 동기화했습니다.

## 2. 원본에서 확인한 문제와 조치

| 문제 | 변경 | 이유 |
|---|---|---|
| 13장, 목차·팀 일정·기술 상세가 본편에 집중 | 7장 본편으로 통합 | 3분 내 설명하고 시연에 시간 배정 |
| BuyTiming과 예전 조장 표기 | PickTiming, 조장·발표자 박미금 | 현재 브랜드와 사용자 지정 반영 |
| Vanilla JS·Bootstrap·폐기된 경로 | React 19·Vite 8·Tailwind v4, 현재 경로 | 실제 코드와 일치 |
| 수집·배포 환경이 혼재 | Netlify 데모, Render 독립 풀스택, EC2 배포 구성 구분 | 데모와 운영 상태를 오해하지 않도록 정리 |
| 설문 비율·F1·응답 시간·환각 0건 | 미검증 성과를 본편에서 제외 | 원자료·측정 보고서 미확인 |
| 긴 설명·피처 표·산식 | 시각적 서비스 흐름·구성도, 설명은 노트 | 비전문가가 핵심을 빠르게 이해 |
| 계정별 권한 차이가 약함 | 회원/관리자 좌우 비교와 조회 전용 안내 | 구현 범위와 접근 권한 명확화 |
| 이전 화면과 스크린샷 | 현재 Netlify 실제 UI 캡처 | 현재 기능의 시각적 근거 제공 |
| 15분 발표·가상 리허설·회의 기록 | 3분+7분, 예정·확인 필요 구분 | 사용자 시간 조건과 사실 기반 기록 준수 |

## 3. 슬라이드 재구성

| 기존 | 최종 | 처리 |
|---|---|---|
| 1 표지 | 1 서비스·팀·발표자 | 정체성 유지, Navy Tech 적용 |
| 2 목차 | 본편 제외 | 진행 흐름을 슬라이드 순서로 전달 |
| 3 개발 배경 | 2 문제→해결→가치 | 설문 수치 제거, 사용자의 실제 질문에 집중 |
| 4 서비스 소개 | 3 흐름 + 5 실제 화면 | 수집·비교·판단·설명·알림 유지 |
| 5 팀·일정 | 표지·단계별 산출물 | 팀원 유지, 세부 일정은 본편 밖으로 이동 |
| 6 시스템, 7 RPA, 8 판정, 9 Gemini | 4 시스템 + 5 기능 | 기술을 역할과 데이터 흐름 중심으로 통합 |
| 관리자 관련 내용 | 6 계정별 기능 | 서버 권한 검사·테스트 관리자 제한 추가 |
| 10 테스트 | 7 검증·시연 전환 | 확인된 기능 검사 결과 사용 |
| 11 시연 | 별도 7분 시나리오 | 동작·멘트·시간·실패 대안 구체화 |
| 12 효과·계획, 13 감사 | 7 기대 가치·감사 | 실측 효과와 기대 효과를 구분 |

향후 계획은 단계별 피드백 산출물에 보존했습니다. 실제 미구현 항목인 카드·쿠폰 조건,
모바일 푸시 등은 완료 기능에 포함하지 않았습니다.

## 4. 디자인 변경

- 판형: 원본의 16:9 유지.
- 색: Deep Navy `#0B1220`, Dark Navy `#111C33`, Blue `#2563EB`, Cyan `#22D3EE`.
- 글꼴: PPT는 Noto Sans KR. 제목 31~47pt, 핵심 본문 19~27pt, 부가 정보 15~17pt 중심.
- 구성: 넓은 여백, 일정한 좌우 기준선, 얇은 연결선·단계별 신호, 절제된 그라데이션.
- 그림: 실제 UI 캡처 외에 제목·카드·구성도·화살표·아이콘은 PowerPoint 기본 도형과 텍스트로 편집 가능.
- 효과: 불필요한 애니메이션 없이 수동 진행. 대본은 발표자 노트에 포함.
- 원본 내용 추적: 원본 PPT 패키지를 읽고 슬라이드를 줄여 재구성하는 제작 스크립트를 보관.

## 5. 근거와 한계

| 항목 | 사용한 근거 | 해석 한계 |
|---|---|---|
| 백엔드 51건·RPA 11건 | 직전 로컬 pytest 및 CI | 제품 정확도·경제적 효과 지표가 아님 |
| 브라우저 9개 시나리오 | Playwright 로컬 회귀 검사 | CI에 자동 등록된 브라우저 검사라고 표현하지 않음 |
| 반응형·접근성 | 375·768·1440px, 검사한 화면·모달 | 모든 기기·보조공학에 대한 인증 아님 |
| 배포 검사 | Actions `41947934806` | 외부 배포의 실제 실행과 구분 |
| Netlify·Render | 실제 새 UI 자산·공개 API 확인 | EC2 실제 운영은 확인 전 |
| AI 설명 | 수치 검증·재요청·대체 응답 코드 | 모든 환각 방지를 보장하지 않음 |
| 상품 화면 | Netlify 실제 UI 캡처 | 상품·가격·계정·답변은 데모 데이터 |
| 발표 시간 | 7장 대본 예산 합계 170초 | 실제 낭독·시연 리허설 시간은 추가 측정 필요 |

테스트 수치는 이번 문서 편집으로 새로 실행한 제품 테스트 결과가 아니라 기준 커밋의 확인 기록입니다.
문서만 변경하므로 검수는 PPT·PDF·HWPX·링크·내용 일치에 집중합니다.

## 6. 기존 docs 개정 범위

- 기존 발표 PPT와 대응 PDF, 제출용 이름의 PPT·PDF.
- 운영 Markdown: 개요·백엔드·프런트엔드·수집·CI/CD·DB·Render·EC2·Netlify·Actions·체크리스트·목록.
- 단계별 산출물 5개: 기획분석·설계·구현·배포·피드백. 원본 서식·표 스타일을 재사용해 내용 개정.
- 진행일지 5개: 원본 표·기간 형식을 유지하고 수행 근거, 미수행 항목, 회의·발표의 확인 상태를 정정.
- HWPX 10개는 설치된 한글에서 다시 열어 저장하고 대응 PDF를 직접 출력.
- 기존 교육 기간·시수는 원본 계획으로 표시. 실제 수행일을 소급해서 만들지 않음.
- 3분 대본, 7분 시연 시나리오, 제작 기준, 캡처 출처, 제작·출력 도구를 추가.

PPT와 PDF는 동일한 내용입니다. 스크린샷 내부 UI는 이미지이며, 앱의 화면 요소처럼 개별 편집되지는 않습니다.
